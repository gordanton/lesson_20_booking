# Драйвер PostgreSQL

`db_driver.py` — это модуль, который из другого проекта ходит в PostgreSQL. Скрипт не собирает SQL вручную: он вызывает методы класса `PostgresDriver`.

Подключение такое же, как в `test_connection.py`. Пароль лежит в `.env`, в код его копировать не нужно.

## Что скопировать в другой проект

1. Файл `db_driver.py`.
2. Свой `.env` в папке, откуда запускаешь скрипт. Файл `.env` в git не кладут.
3. Две библиотеки из `requirements.txt`:
   - `psycopg2-binary` — связь Python с PostgreSQL;
   - `python-dotenv` — чтение `.env`.

Установка в виртуальное окружение:

```powershell
pip install -r requirements.txt
```

`.env` выглядит так:

```text
DB_HOST=localhost
DB_PORT=5432
DB_NAME=test
DB_USER=user
DB_PASSWORD=пароль
```

`DB_HOST` по умолчанию `localhost`, `DB_PORT` — `5432`. Остальные три переменные обязательны. Если их нет, драйвер выбросит `DatabaseConfigError`.

Если `.env` лежит не в текущей папке, передай путь:

```python
db = PostgresDriver(env_file=r"C:\path\to\.env")
```

## Сначала нужна таблица

Драйвер умеет добавлять, читать, менять и удалять строки. Создать таблицу он не умеет: это отдельная команда SQL, `CREATE TABLE`.

Пример таблицы для журнала работ:

```sql
CREATE TABLE IF NOT EXISTS work_log (
    id SERIAL PRIMARY KEY,
    title TEXT NOT NULL,
    hours INTEGER
);
```

`SERIAL PRIMARY KEY` значит: база сама выдаёт номер `id`, и этот номер у каждой строки свой.

В примере проекта это делает команда `python main.py init`. В своём проекте ту же команду можно выполнить в клиенте PostgreSQL (pgAdmin, DBeaver, psql).

## Как вызвать драйвер

```python
from db_driver import PostgresDriver

db = PostgresDriver()
```

Имя таблицы передаётся строкой: `"work_log"` или `"схема.таблица"`. Словарь `data` — это «столбец → значение». Словарь `filters` — условия «столбец равен значению». Несколько условий склеиваются через AND: подойдут только строки, у которых совпали все поля.

### create — добавить строку

Соответствует SQL-команде `INSERT`. Возвращает вставленную строку, включая `id`.

```python
row = db.create("work_log", {"title": "Сверка часов", "hours": 8})
print(row["id"])
```

Пустой словарь передать нельзя.

### read — прочитать строки

Соответствует `SELECT`. Возвращает список словарей. Пустой список значит, что ничего не нашли.

```python
rows = db.read("work_log")
rows = db.read("work_log", filters={"title": "Сверка часов"})
rows = db.read(
    "work_log",
    columns=["id", "title", "hours"],
    limit=20,
)
```

Без `filters` метод заберёт все строки. На большой таблице всегда передавай `limit`.

### read_one — прочитать одну строку

Тот же `SELECT`, но ожидается не больше одной строки.

```python
row = db.read_one("work_log", filters={"id": 1})
```

- ничего не нашли — вернётся `None`;
- нашли несколько — будет `ValueError`. Тогда фильтр слишком широкий, бери `read()`.

`filters` здесь обязателен.

### update — изменить строки

Соответствует `UPDATE`. Возвращает список уже изменённых строк.

```python
updated = db.update("work_log", {"hours": 10}, filters={"id": 1})
```

`filters` обязателен. Без него один вызов перезаписал бы всю таблицу, поэтому драйвер такой вызов отклоняет.

### delete — удалить строки

Соответствует `DELETE`. Возвращает число удалённых строк, не сами строки.

```python
deleted = db.delete("work_log", filters={"id": 1})
```

`filters` тоже обязателен. Пустой фильтр метод не примет.

## Пример проекта в этой папке

`main.py` — журнал работ. Он показывает, как внешний код пользуется драйвером.

Из папки проекта, с включённым виртуальным окружением:

```powershell
python main.py init
python main.py add "Сверка часов" 8
python main.py list
python main.py show 1
python main.py update 1 10
python main.py delete 1
```

`init` один раз создаёт таблицу `work_log`. Остальные команды ходят в неё только через `PostgresDriver`. Номер в `show`, `update` и `delete` — это `id` из колонки списка.

## Ошибки, которые ловит внешний проект

Драйвер сам ничего не печатает. Ошибку видит тот скрипт, который его вызвал.

| Ситуация | Какая ошибка |
| --- | --- |
| Нет `DB_NAME`, `DB_USER` или `DB_PASSWORD` | `DatabaseConfigError` |
| Сервер выключен, неверный пароль, хост или порт | `psycopg2.OperationalError` |
| Таблицы нет или опечатка в имени столбца | `psycopg2.Error` |
| Пустой `data`, пустой `filters` у update/delete/read_one | `ValueError` |

В `main.py` эти ошибки пойманы и напечатаны коротким текстом. Так и стоит делать в своём проекте: не показывать пользователю сырой текст библиотеки, если можно сказать, что именно проверить.

## Ограничения

- Один вызов — одна транзакция. Транзакция здесь — пачка команд, которая либо целиком сохраняется, либо целиком отменяется. `create` и следующий за ним `update` — это уже две отдельные пачки. Если вторая упадёт, первая не откатится.
- Фильтр умеет только равенство. Поиска «название содержит текст», сравнения «часы больше 8» и сортировки в драйвере нет.
- Чтобы найти пустое поле, передай `None`: `filters={"hours": None}`. В SQL сравнение `hours = NULL` не находит такие строки, поэтому драйвер сам пишет `IS NULL`.
- Имена таблиц и столбцов должны совпадать с базой. Значения при этом в команду подставляются отдельно, как параметры. Из-за этого текст из словаря не может превратиться в чужую SQL-команду.
